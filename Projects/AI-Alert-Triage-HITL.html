AI-assisted alert triage with human-in-the-loop

An AI triage layer on Microsoft Sentinel that cuts alert fatigue without giving the AI any power to act. The question is not whether AI can be plugged into a SOC, but whether its conclusions can be trusted, where they are wrong and whether an attacker can use them.

Microsoft Sentinel Azure OpenAI Logic Apps Defender for Endpoint Prompt Injection Human-in-the-loop
Planning · GitHub repository

How it works

One incident, from creation to the analyst's decision.

StepWhat happens
1An incident is created in Microsoft Sentinel and an automation rule starts a Logic App
2KQL gathers the related alerts, entities and surrounding logs, pre-aggregated and enriched from watchlists
3Azure OpenAI returns a structured triage in which every claim cites a log record that exists in the input
4Deterministic routing sends the incident to approval-gated execution or straight to an analyst
5The analyst decides; an approved device isolation runs through a separate, rate-limited playbook

Design decisions

Written down before building, so the claims stay honest.

  • The AI never acts on its own There are 2 modes only: human approval then execution, or full human triage. There is no autonomous mode.
  • Routing is code, not the model Model confidence, policy exceptions, ambiguity and asset impact are computed deterministically, with thresholds versioned in Git.
  • Two identities, one job each The triage identity can read data and write comments, and a negative test proves it cannot do more. Only the execution playbook can isolate a device.
  • No automatic closing A wrongly closed true positive is a silent miss, and 0 misses in 10 true positives still leaves an upper bound of about 30% at 95% confidence.
  • Alert fields are untrusted input Usernames, command lines and file names can be written by an attacker, so they are isolated, scanned with Prompt Shields and never rendered as links.

What gets measured

Against a ground-truth set I labelled and committed before the AI ever ran.

MeasureWhy it matters
Missed true positivesThe most expensive error, reported on its own
Coverage and routing errorsAn AI that always defers to a person has no misses and no value
Fabricated evidenceEvery cited value is checked automatically against the input
Triage time and queue rankingWhether alert fatigue actually goes down
Prompt injection success ratePlanted in alert fields, before and after the guardrails

Deliverables. The pipeline deployed with Terraform, the labelled ground-truth set and evaluation scripts, an evaluation report, a postmortem and a one-page note on what the AI can and cannot do in this workflow. All data comes from my own labs; no customer data.
